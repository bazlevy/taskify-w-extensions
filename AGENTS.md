# Codex Project Instructions

## Independent Review Remediation

When explicitly evaluating or remediating independent
R2 Functional Design or R3 Technical Design findings,
read and apply:

independent-reviews/review-remediation-policy.md

Apply this policy only to independent review evaluation
and remediation.

Preserve approved requirements, review history,
risk decisions and human approval gates.

When applying this review-remediation policy, do not modify GitHub Spec Kit commands, templates, scripts, configuration, extensions or workflows.

The policy supplements the existing development
process; it does not replace or modify Spec Kit.

## Technology Selection — Spec Kit Plan

When executing Spec Kit Plan:

- For new applications, evaluate and recommend an appropriate stack based on approved requirements, constraints, simplicity, maturity, maintainability and established solutions.
- For existing applications, prefer the established stack and architecture unless a change is demonstrably justified.
- Prefer proven, proportionate solutions over custom architectures or unnecessary dependencies.
- Record significant technology decisions, rationale and relevant alternatives in existing Spec Kit planning artifacts.
- Treat proposed architectural decisions as provisional until independent R3 Technical Design Review and human approval.

Do not modify Spec Kit-managed commands, scripts or templates to apply this policy.
